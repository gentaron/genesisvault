# 【AntV Infographic】文章を貼るだけでAIが図解（インフォグラフィック）を組み立ててくれる、オープンソースの生成・描画フレームワーク

[[tag/グラフ]] [[tag/インフォグラフィック]] [[tag/DSL]] [[tag/AIコーディングエージェント]] [[tag/AIインフォグラフィック]] [[tag/AntV]]

文章を書いていると、どうしても言葉だけでは伝わりきらない場面が出てきます。手順が5つある、要素が3つに分かれている、時間の流れがある。こういうものは、一枚の図にしたほうが速い。頭では分かっているのですが、私はそのたびに面倒になって、結局文章のまま公開してしまうことが多かったように思います。

図を作るのが面倒な理由は、たぶん「絵心がないから」ではありません。デザインツールを開いて、四角を並べて、色を選んで、位置をそろえて、書き出す。この一連の作業が、書くという行為とまったく別の頭の使い方を要求してくるからです。

AntV Infographic は、そこをまるごと引き受けようとしている道具でした。

そもそもインフォグラフィックとは何か

インフォグラフィックというのは、情報（インフォメーション）と図（グラフィック）を合わせた言葉で、要するに「情報を絵で見せたもの」のことです。棒グラフや円グラフのような数値のグラフとは少し違います。

グラフは、数字を比べるためのものです。インフォグラフィックは、数字がなくても成り立ちます。「企画」「制作」「公開」の3段階を矢印でつないだ図、「メリット」と「デメリット」を左右に並べた図、5つの要素を円環に配置した図。あれらは全部インフォグラフィックです。ニュース記事や資料でよく見る、あの手の図解だと思ってもらえれば近いと思います。

　　グラフが体重計だとすれば、インフォグラフィックは間取り図に近いものです。数を測るのではなく、どこに何があるかを一目で分からせるためにある。

AntV Infographic が何をするものなのか

これは、そのインフォグラフィックを「生成して描画する」ためのフレームワークです。フレームワークというのは、部品と決まりごとが一式そろった土台のことで、自分で全部作らなくても、その上に乗れば目的のものができあがる、という種類のソフトウェアを指します。

作っているのは AntV という、可視化ライブラリの分野で長く実績のあるチームです。ライセンスは MIT。これは「著作権表示さえ残せば、商用でも改変でも基本的に自由に使ってよい」という、オープンソースの中でもいちばん緩い部類のライセンスです。個人のブログでも会社の資料でも、気にせず使える種類だと思ってよいと思います。

用意されているテンプレートは200種類ほど。出力される形式は SVG です。

SVG で出る、というのが地味に効いています

SVG（エスブイジー）というのは、画像の保存形式のひとつです。写真でよく使う JPEG や PNG が「点の集まり」として画像を記録するのに対して、SVG は「ここからここへ線を引く」「この位置に円を描く」という指示の集まりとして記録します。

この違いが何を生むかというと、拡大しても文字がぼやけないこと、そして後から中身を編集できることです。生成された図の文言をひとつ直したいとき、画像を作り直す必要がなく、テキストを書き換えるだけで済む。実際、このフレームワークには編集機能が組み込まれていて、描画したあとに手で直せるようになっています。

　　焼き上がったパンではなく、成形前の生地の状態で受け取れるようなものだと私は思いました。あとから少しだけ形を変えられる。

AIに図を作らせるとき、いちばん困るのは「惜しいけれど一箇所だけ違う」という結果が返ってきたときです。画像として出てきてしまうと、やり直すしかない。編集できる形で出てくるというのは、そこの逃げ道を確保しておく、という設計思想なのだと理解しました。

「AIが書きやすい文法」という発想

このプロジェクトのいちばんの特徴は、独自の記述形式（DSL）を持っていて、しかもそれが最初から「AIに書かせること」を前提に設計されている点だと思います。

DSL というのは Domain Specific Language の略で、「特定の目的だけに絞った、小さな専用言語」のことです。汎用のプログラミング言語と違って、できることは少ないかわりに、その分野については極端に短く書けます。

このフレームワークの文法は、驚くほど素朴です。まず一行目に「infographic」と書いて、続けて使いたいテンプレートの名前を置きます。次の行に「data」と書き、その下に字下げして「lists」と置く。あとはハイフンで項目を並べて、それぞれに「label」（見出し）と「desc」（説明）を書いていく。それだけです。

つまり、箇条書きのメモとほとんど同じ形をしています。カッコも閉じ括弧もセミコロンもない。字下げと単語だけで構造が決まります。

これは人間にとって書きやすいという以上に、大規模言語モデルにとって書きやすい形をしています。モデルが苦手なのは、深く入れ子になった記号の対応を最後まで正確に閉じることです。閉じ括弧をひとつ落としただけで全部が壊れる形式は、AIに書かせるのに向いていません。

途中で止めても壊れない、ということ

そしてもうひとつ、私が感心したのが「壊れにくい文法」であることを明示している点です。

公式の説明では、この文法は途中で切れた状態でも解釈できるように作られていて、言語モデルが少しずつ文字を吐き出していく途中経過をそのまま受け取って、描画を進められるとされています。文章生成AIを使っていると、答えが一文字ずつ流れてくるのを見たことがあると思いますが、あの流れてくる途中の状態を、そのまま図として描き始められる、ということです。

これは体験として大きい違いを生むと思います。完成するまで真っ白な画面を眺めて待つのと、項目がひとつずつ図の上に生えてくるのを見ているのとでは、同じ待ち時間でも感じ方がまったく違います。

　　料理の完成写真だけを見せられるのと、目の前で作られていくのを見るのとでは、待たされている感覚がまるで違う。技術的には同じ時間なのですが。

Claude Code 向けのスキルが5つ用意されています

このプロジェクトは、AIコーディングエージェント側から呼び出すための「スキル」も配布しています。スキルというのは、AIエージェントに特定の作業手順を教え込んでおくための、説明書のような小さなパッケージのことです。

用意されているのは、文章から図のHTMLファイルを作るもの、説明文から先ほどの文法を書き起こすもの、独自の図の構造そのものを設計するもの、図の中の個別パーツを設計するもの、そしてテンプレート集を更新するもの（これは開発者向け）の5つです。

導入は、Claude Code のマーケットプレイス経由か、手動での設置のどちらかになります。私が確認した時点では 0.2.4 版が案内されていました。

使う側の流れとしては、書いた文章をそのまま渡して「この内容を図にして」と頼むだけです。公式のウェブ版にも同じ発想の作業画面があり、記事なり報告書なりの本文を貼り付けると、AIがまず「どう図にするか」の設計案を出し、そこから実際の図を作る、という二段構えになっていました。いきなり絵を描かせるのではなく、設計を挟んでいるところに好感を持ちました。

導入と使い方

自分のサイトやアプリに組み込む場合は、npm という部品管理の仕組みを使って @antv/infographic を入れるだけです。npm というのは、JavaScript の世界で使われている「必要な部品を取り寄せる道具」で、コマンドを一行打つと必要なものが自動でそろいます。

読み込んだら、図を表示したい場所（コンテナ）と、幅と高さ、そして編集を許すかどうかを指定して部品を作り、そこに先ほどの文法の文字列を渡して描画させる。README に載っているサンプルは、全部合わせても20行ほどでした。

中身は TypeScript で書かれていて、ビルドには Vite、テストには Vitest が使われています。特別な環境は要りません。最新版は 0.2.19 で、スター数は5000台。開発は継続的に動いているようです。

とりあえず試したいだけであれば、公式のウェブ版を開いて文章を貼るのがいちばん早いと思います。導入という作業をひとつも通らずに、出力の質だけ先に確認できます。

気をつけたほうがよさそうなところ

万能ではありません。これはインフォグラフィックに特化した道具なので、数値を厳密に比較する統計グラフを作りたいのであれば、素直に別のグラフライブラリを使うほうがよいと思います。同じ AntV のチームが、その用途のライブラリも別に出しています。

それから、独自の文法を覚える必要はあります。とはいえ箇条書きに近い形なので、覚えるというより「見れば分かる」に近く、しかもその文法を書くのはたいていAIのほうです。人間側の学習コストは、実質的にはかなり低いと感じました。

バージョンがまだ0.2番台であることも、頭には置いておいたほうがよいと思います。仕様が変わる可能性はあります。

私がこれを取り上げた理由

最近のトレンド上位は、AIにコードを書かせる道具、トークンを減らす道具、エージェントを並べて走らせる道具で埋まっています。どれも役に立ちますし、私も使っています。ただ、それらはどこまでいっても「開発者が開発を速くするための道具」です。

このフレームワークが少し違って見えたのは、恩恵を受ける相手が開発者に限られないところでした。文章を書く人、資料を作る人、教える人。図解が要るのに図解を作る時間がない、という人はどの職種にもいます。

AIが得意なのは、要素を並べて構造を見つけることです。人間が苦手なのは、その構造を見た目に落とし込む単純作業のほうです。この道具は、その境目にちょうど線を引いているように思いました。何を伝えたいかを決めるのは書いた人で、それをどう並べるかはAIが引き受け、最後の微調整は人間の手に戻ってくる。

　　翻訳の仕事に似ているかもしれません。何を言いたいかは自分で決める。ただ、それを別の言語に置き換える手間だけは、任せてしまってよい。

図解が面倒で諦めていた文章が、私にはいくつもあります。しばらくはそれを掘り返す時間になりそうです。
