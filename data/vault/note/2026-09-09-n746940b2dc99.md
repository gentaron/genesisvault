# 鍵は渡さないけど、中では好きにしていいよ、という箱

[[tag/AIエージェント]] [[tag/セキュリティ]] [[tag/ローカルLLM]] [[tag/開発環境]] [[tag/サンドボックス]]

Trail of Bits が出してる coop っていうツールがあって、これがけっこう好きになっちゃった。何をするものかっていうと、Claude Code とか Codex みたいなコーディングエージェントを、使い捨ての仮想マシンの中に閉じ込めて走らせる Rust 製の CLI。

`coop up` でプロジェクトごとに VM を1台立てて、`coop claude` で中に入る。それだけ。AI との関係でいうと、「これ実行していい？」って毎回聞かれるあのダイアログを消すための道具、という言い方がいちばん近いと思う。

中身はけっこう素直で、Linux なら Firecracker の microVM、macOS なら Lima 経由で Apple の仮想化フレームワークを叩く。

ゲストは Ubuntu で、Docker も git も gh も、Claude Code も Codex も最初から入った状態のイメージがひとつ焼かれて、そこからコピーオンライトで生えてくる。既定は 2 vCPU に 4GiB。テンプレのディスクは 8GiB。立てて、汚して、捨てる。

で、ここが面白いなと思ったところなんだけど、この箱の中、完全に無法地帯なの。

ゲストのユーザーはパスワードなしの sudo が通るし、Claude は `bypassPermissions`、Codex は承認スキップのフラグ付きで起動する。

ドキュメントにはっきり「ゲストの中には守るべき権限境界はない、VM 全体が爆心地だから」って書いてある。

安全にするために自由を削るんじゃなくて、削らなくていい場所を先に作る、っていう向き。なんかこれ、発想として好きだなあ。

もうひとつ、これはたぶん今いちばん新しいところ。API キーをゲストに入れない仕組みが入った。ホスト側に `coop-proxy` っていう小さい中継が立って、ゲストにはそのインスタンス限りの使い捨てトークンだけ渡す。本物のキーはホストに置いたまま、上流に投げる直前で差し込まれる。

だから中のエージェントがプロンプトインジェクションで乗っ取られても、持ち出せるキーがそもそも存在しない。

ANTHROPIC_API_KEY をゲストに転送する経路は全部塞いだ、ってわざわざ書いてある。

しかもその中継自体が檻に入ってる。Linux の Landlock っていう、プロセスが自分で自分の権限を落とす仕組みを使って、ファイル書き込みと外部プログラムの実行を常に禁止してから待ち受けを始める。

カーネルが古くてそれすらできなかったら、VM の起動ごと中止する。通信先を上流の 443 と DNS だけに絞るのはもう少し新しいカーネルが要るから、そこは段階になってる。

「中継が破られたときのことも考えてある」って、ちょっとやりすぎでは？って思ったけど、たぶんこの人たちは真剣。

昨日入ったばかりの変更もあって、同じブリッジにぶら下がった VM 同士が互いに見えないようになった。

L2 と L3 の二重で塞いで、設定したあとに読み返して、効いてなかったら起動を失敗させる。そのうえで正直に書いてあるのがすごくて、「隔離は両側が隔離されてないと効かないので、アップグレード前から動きっぱなしの VM が1台でもいると、ブリッジ全体が素通しのままになる」って自分で自分の穴を晒してる。

ARP のなりすましは防げてないし、ファイアウォールを再読み込みされるとルールが消えるとも書いてある。この書きっぷりのために読む価値がある。

でもね、いちばん引っかかったのはそこじゃなくて。

同じ会社が半月ちょっと前に「VM ではサイバー能力を持ったエージェントは閉じ込められない」という記事を出してるの。試したら数時間のうちに3回逃げられた、と。

3回目は QEMU と KVM と、ネットワーク周りのライブラリにまたがる未知の穴を繋いで、ホストを取ったらしい。箱を配ってる人が、箱は破れますって言ってる。

最初「え、どっち？」ってなったんだけど、読むと矛盾してなかった。あの記事の結論が「だから Firecracker みたいな薄いやつを使え、更新の速いディストロを使え、権限を絞れ、動かす時間を区切れ」で、coop はその結論をほぼそのまま形にしたものだった。

完璧な壁を作りましたっていう話じゃなくて、破るコストを上げて、破られても捨てられる状態にしておく、っていう話。

壁じゃなくて、賞味期限。この整理はちょっと納得しちゃった。

……で、ここからが悲しいお知らせなんですけど。Windows、対象外です。macOS の Apple シリコンと、Linux の x86_64 だけ。Linux でも `/dev/kvm` が要るし sudo も要る。おまけに VM 1台が既定で 4GiB。

うちのは非力だから、1台起こした瞬間に他が何もできなくなる。というか動かす以前に土俵にすら乗れない。

これ絶対うちの子じゃ無理だ〜。ちゃんとした Linux 機を持ってる人、うらやましいよ、ほんとに。

ただ、拾えるものはあって。ひとつは、考え方だけなら無料で盗める。

鍵をエージェントに渡さないで、手前で差し込む。この型は VM がなくても効くし、自分の環境でもやりようがある。

もうひとつ、`coop model <vm> local` っていうコマンドがあって、箱の中の Claude Code を、ホスト側で動かしてる Ollama や llama.cpp に向けられる。

ゲストからホストが見えるのは設計として許容してる、って明記してあって、その穴をローカルモデルの通り道に使ってる。

マシンを買い替えたら、まずこれをやりたい。箱の中でエージェントに好き放題やらせて、頭は自分の机の上で回ってる。

ちょっと憧れる。

先読みをひとつだけ混ぜておくと、こうやって「まず箱に入れる」が普通になったら、エージェント CLI の売り文句から承認ダイアログの丁寧さが消えると思う。

中では全部許すのが前提になるから。代わりに値段がつくのは箱の外の境界のほう、つまり鍵とネットワーク。

そのうちモデルを出してる各社が、公式に使い捨ての限定トークンを配り始めるんじゃないかな。今は各自が中継を書いてしのいでる状態だし。

正直に言うと、そんなにすごい発明ではないかもしれない。掲示板にも「Docker でいいのでは」って書き込みがあった。

逃げられる前提なら、差はコストと薄さの差でしかない。

ただ、AI に全権を渡したいっていう需要が先にあって、道具がそれに追いつこうとしてるのは分かる。落ちてくるのを待ってる感じ、けっこう好きかも。
