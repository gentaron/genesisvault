# 【ActiveGraph】ログは、エージェントの元帳だった

[[tag/AI]] [[tag/記録]] [[tag/構造]] [[tag/形式検証]] [[tag/グラフエンジニアリング]] [[tag/ニューロシンボリックAI]] [[tag/ActiveGraph]]

グラフエンジニアリングとニューロシンボリックが、ここで一度合流したと思う

ActiveGraphというエージェント・ランタイムを何日か触って読んで、最初に持った感想を正直に書くと、「これ、記憶の話じゃないな」でした。

私は最初、完全に読み違えていました。追記専用のイベントログが真実で、グラフはその投影で、ビヘイビアが変化に反応してイベントを吐く——という説明を見て、「ああ、リッチなメモリ層ね」と思ったんです。ZepとかMem0の系統だろう、と。

違いました。あれは記憶の設計ではなくて、会計の設計でした。そして私にとって面白かったのは、そう気づいた瞬間に、グラフエンジニアリングとニューロシンボリックAIという、私の中で別々の棚に置いてあった2つが、同じ棚に並んだことでした。

まず、動き方の絵を描いてみる

言葉で説明するより、私が理解のために描いた絵を貼った方が早いと思います。

   ┌──────────────────────────────────────┐
   │                                      │
   ▼                                      │
┌─────────────────┐                       │
│  イベントログ    │  ← 追記のみ。消えない  │
│  (真実はここ)    │                       │
└────────┬────────┘                       │
         │ replay（決定的な畳み込み）        │
         ▼                                │
┌─────────────────┐                       │
│  グラフ（投影）   │  型付きオブジェクト     │
│                 │  ＋型付きエッジ         │
└────────┬────────┘                       │
         │ 形状パターンに一致すると発火      │
         ▼                                │
┌─────────────────┐                       │
│  ビヘイビア      │ 関数 / クラス /         │
│  （反応）        │ LLM / エッジ上のロジック │
└────────┬────────┘                       │
         │ 新しいイベントを吐く              │
         └──────────────────────────────────┘

要するに、ログ→グラフ→反応→ログ、という一方通行の輪。
グラフを直接書き換える手段は、どこにも用意されていない。

この「グラフを直接書き換えられない」が全部だと思います。状態を触る唯一の方法がイベントを足すことだけなので、履歴が嘘をつけない。

グラフエンジニアリング側から見ると、何が新しいのか

私はグラフを「検索と推論のためのデータ構造」として見る癖がありました。ノードに情報を持たせて、エッジは関係を表す線で、クエリで辿るもの。

ActiveGraphで一番手が止まったのは、エッジに計算が乗るという発想です。リレーション・ビヘイビアといって、型付きの辺そのものにロジックが貼り付く。つまり「AとBを関係づけるという行為」が計算の起点になる。

これ、地味に見えて発想の転換だと思うんですね。従来なら「関連イベントを出すかもしれない全ノード」に同じ調整ロジックを複製することになる。でも意味が宿っているのは、たいていノードじゃなくて関係の方なんです。「この主張は、あの文書から派生している」「この主張は、あの質問に答えている」。意味はエッジにある。だったら計算もエッジに置け、と。

もうひとつ、購読の条件がイベント型ではなくグラフの形である点も大きいです。「まだ答えの出ていない質問に対応する主張が現れたら発火する」みたいな、トポロジーに対する述語で待ち構えられる。

フラットなイベントストリームだと、受け取る側が毎回グラフを組み直さないとこれは書けません。

ログだけなら「現在値」しか投影できない。
グラフだから「形」で待てるし、2つの実行を構造で差分できる。
私はここで、ログとグラフはどちらか一方では足りないのだと納得しました。

ニューロシンボリックとして見ると、境界線の引き方が上手い

ニューロシンボリックAIって、ずっと「どこで神経と記号を継ぐか」の問題だったと私は思っています。

記号側に寄せると脆くなり、神経側に寄せると説明できなくなる。

ActiveGraphの継ぎ方が私には新鮮でした。線を引いているのが、機能ではなく時間なんです。

【初回実行】
  記号側 ───────┐
  型・グラフ・   │
  決定的な投影   │
                ├──▶ LLMビヘイビアは自由に呼ぶ
  神経側 ───────┘     （非決定的でOK）
                       応答はイベントとして記録される
                              │
                              ▼
                     ┌─────────────────┐
                     │ 内容アドレスの    │
                     │ 応答キャッシュ    │
                     └─────────────────┘
                              │
【リプレイ】                   ▼
  記号側だけが動く ◀── 記録済み応答を配る
  （新しいモデル呼び出しは0回）

初回は神経が自由に暴れていい。
2回目以降、その暴れっぷりは記号側の資産に変わる。

つまり「モデルを決定的にする」のではなく、「モデルの出力を、記号側の台帳に一度書き込んでしまう」という解き方をしている。私はこれを、非決定性を否定するのではなく凍結するやり方だと理解しました。

だから再現できるのは「エージェントを走らせること」ではなく「既にあるログを再投影すること」だけ。この区別を曖昧にしていない点が、私はかなり好きです。

再現性を売りにする道具はたいていここをごまかすので。

そしてこの凍結があるから、フォークが安くなる。200ステップの実行の150ステップ目で設定を1つ変えて分岐しても、前半149ステップはキャッシュから配られるだけで、モデル呼び出しの費用は発生しない。反実仮想の実験が、思考実験ではなく普通の操作になります。

これは1980年代の敗者復活戦でもある

もうひとつ、私が唸ったところ。

共有された知識構造があって、独立した部品がそこから読んで書き戻し、互いに直接命令しない——この構造、ブラックボード・システムそのものなんですよね。1970年代から80年代の、古典的な記号AIの設計です。

当時これがスケールしなかった理由は2つあったと私は理解しています。ひとつは、書き込む部品が手作りの狭いルールで脆かったこと。もうひとつは、「次にどの部品が動くべきか」という制御を人間が手で書かなければならなかったこと。

LLMは、その2つを両方溶かしてしまった。部品は汎用のLLMルーチンでいいし、制御は自然言語で書けるか生成できる。

ブラックボードは間違っていたのではなく、早すぎた。
足りなかったのは知能ではなく、
共有状態をリプレイ可能・分岐可能にする基盤だった。

私はこの見立てを聞いたとき、ニューロシンボリックという言葉の解像度が少し上がった気がしました。神経と記号を「混ぜる」んじゃなくて、記号側が用意した舞台の上で神経に演じさせて、演技をログに焼き付ける。混合ではなく、分業と記録なんだ、と。

私が浮かれすぎないように書いておくこと

ただ、ここまで書いておいて何ですが、私はこれを万能だとは思っていません。

反応が反応を呼ぶ構造なので、実行が発散したりループしたりする余地が原理的にあります。防御は実行ごとの上限（イベント数、モデル呼び出し数、再帰の深さ、時間、コスト）で、これは鈍器であって停止の保証ではない。

リプレイの費用はログの長さに比例するので、本当に長生きするエージェントはいずれ圧縮の仕組みが要ります。イベントの型を後から変えるスキーマ進化も、実運用の負担として残る。

そして一番現実的な穴だと私が思うのは、外の世界を書き換えるツールです。決定的にリプレイされるのは「そのツールを呼んだ記録」であって、送ったメールは戻ってきません。

さらに言えば、この設計は「精度が上がる」とは主張していません。売っているのは性能ではなく性質です。

だから私の結論は、こうなりました。答えの正しさと同じくらい「なぜそう答えたか」が商品になる領域——調査、監査、規制対応、研究——では、この重さは払う価値がある。逆に、一発で答えが出て誰も後から問い直さないタスクには、完全に過剰です。

最後に

私がこの数日で一番変わったのは、エージェントを「賢さ」で評価する癖が少し薄れたことでした。

複式簿記が商業を変えたのは、それが儲かるからではなく、後から検証できるようになったからだと私は思っています。エージェントに元帳を持たせるというのは、たぶんそれと同じ種類の話で、賢さの話じゃない。

グラフは意味を保つための構造で、ログは時間を保つための構造。

その2つを重ねた上で、神経の非決定性を記録という形で記号側に引き渡す。ニューロシンボリックの合流点は、推論エンジンの中ではなく、案外こういう地味な台帳のところにあったのかもしれないな、と今は思っています。
