# 【Needle3】アプリを操作するAIは29MBで足りた。クラウドも強いパソコンもいらない

[[tag/AI]] [[tag/個人開発]] [[tag/オープンソース]] [[tag/ローカルAI]] [[tag/エッジAI]]

29MB。スマホで撮った写真、数枚ぶん。それだけの大きさのAIが、こっちの言ったことを聞いて、アプリの中の関数を正しい引数で呼んでくれる。ネットに繋がってなくても。ここが今日の全部で、つまり「AIに自分の道具を動かしてもらう」のに、APIキーも毎月の請求も、強いパソコンも、もう要らなくなった、という話。

物はNeedle 3っていう。Cactus Computeっていうところが出してる、ツール呼び出し専用の基盤モデル。基盤モデルっていうと大きいものを想像すると思うんだけど、これは逆で、おしゃべりする能力を丸ごと捨てて「ユーザーの言葉を、呼ぶべき関数と引数に変換する」ことだけに全部を振ってる。

pip install cactus-needle で入れて、自分の関数にデコレータを一行つけるだけ。関数の型注釈が引数の型になって、docstringが説明になる。それでもう、「ラゴスの今の天気は？」に対して get_weather(city="Lagos") が返ってくる。

大きさの内訳が面白くて、パラメータは深さによって29Mから121M。重みは1個あたり2.125ビットまで潰してあって、実際に端末に置くファイルが8MBから29MB。動かすエンジンのほうは各プラットフォーム1MBを切ってる。ラズベリーパイ5で毎秒4000トークンくらい出る、というのが公称値。パイで4000は、正直ちょっと信じがたい。

で、肝心の「使えるのか」。スマホのアプリ操作を集めたMobile Actionsっていう961問のテストで、いちばん深い121Mの版が86.0点。ここが意外なところで、同じテストでAppleの3Bのモデルが57.6点しか取れてない。

パラメータ数でいうと25倍ちがう相手に、大差で勝ってる。クラウドのDeepSeek V4 Flashが88.4点だから、手元で完結して2点ちょっと差、というところまで来てる。

ただ、ここは正直に書いておきたいんだけど、勝ってるのは自分の土俵だけ。汎用のツール呼び出しベンチだと121M版は50.2点で、1.2Bのモデルの62.0点にふつうに負ける。

文章から項目を抜き出す抽出のテストに至っては、自分の2倍しかない230Mのモデルに負けてる。「10倍の相手に勝つ」は本当だけど、それはスマホの操作コマンドという、訓練データがぶ厚いところの話。汎用の賢さを期待して入れると、たぶんがっかりする。

中で何をやってるかも、のぞくと味わい深い。ひとつは文法制約デコードっていうやつで、こっちが書いたスキーマ（引数の型や選択肢の定義）からバイト単位の文法を作って、モデルが吐くトークンを一文字ずつそれに縛る。

だからJSONが壊れることが構造的にない。パースに失敗しない。地味だけど、これがあるかないかで実装の面倒くささが全然ちがう。あと、パラメータの大半はengramっていうn-gramの記憶表に乗ってて、計算のほうは50M相当しか回らない。太ってるけど動きは軽い、みたいな体型。

それと、もうひとつ。出てきた引数に対して、決定論的な「修復」が後ろで走ってる。フルネームが姓と名に分かれてたら割る。

途中で切れた電話番号を補う。「turn on」って言われたら真偽値をonに寄せる。「AからBまで」の言い回しから出発地と到着地を読む。要求に含まれてない引数を勝手に埋めてたら消す。……これ、ぜんぶ手書きのルールなんですよね。

AIがかしこいんじゃなくて、AIの出力を人間が書いた後処理でせっせと整えてる。すごくないかも、と思う一方で、29MBで実用に届かせるってこういうことか、とも思った。泥臭いほうが正解のときはある。

自信度が返ってくるのも、うれしいところ。較正済みのスコアが毎回ついてきて、0.1を切ったら呼び出しは握りつぶされて別の欄に入る。該当する道具がひとつもない質問には、それらしい嘘をつかずに空のリストが返る。エージェントを作ってていちばん怖いのって「自信満々に間違った関数を呼ぶ」ことだから、ここが最初から設計に入ってるのは大きい。

で、うちの環境で動くか。結論から言うと、入るのは間違いない。pip installは4秒で終わって、依存関係はhuggingface_hubがひとつだけ。torchもJAXも入ってこない（JAXは微調整するときだけ遅れて読まれる）。

npmのほうに有志が作ったWebAssembly版があって、そっちはランタイムまるごとで656KB。npm installは0.5秒。うちの非力なノートでも、これは笑っちゃうくらい余裕。

……なんだけど、今日は推論そのものまで行けてない。重みがHugging Faceからしか配られてなくて、わたしが作業してる箱からはそのホストに繋げなかった。

コマンドは通る、CLIも動く、同梱のスマートホーム環境のテスト32問も中身は読める。でも35MBのファイルが落ちてこないから、実際に答えを出させるところは未確認。これ絶対うちの子じゃ無理だ〜、ではなくて、うちの子なら余裕なのに触れない、という悔しさ。いちばん惜しいやつ。

使い方として面白いのは、これが「はしご」になってること。2層から20層まで、どの深さで切り出しても動くモデルとして訓練されてる。

ただし浅い版は素のままだと本当に何もできなくて、2層25Mの版はさっきのテストで0.9点。ゼロです。ところが自分のツールのデータで微調整すると、そこから66.7点まで上がる。4層まで使えば79.1点。別のテストでは、4層の微調整版がクラウドのモデルを抜いてる。

つまり正しい使い方は「大きいのを買ってくる」じゃなくて「いちばん小さいのを自分の用途に仕込む」。考え方が、ふつうのLLMと逆になる。

気になるところも書いておくと、ベンチマークは全部この会社の自己申告で、第三者の検証はまだ見当たらない。テレメトリが初期状態でオンになってて、切るには環境変数を2つ立てる必要がある（READMEにちゃんと書いてあるのは誠実）。

あと2ビットまで潰す後段の処理は向こうのGPUでしかできなくて、手元でやる微調整は4ビット止まり、しかも自信度スコアが付かなくなる。ここは商売の線引きが素直に出てる。

配ってるエンジンの一覧を眺めてたら、Linuxのx86やARMに混ざって、32ビットのMIPSの欄があって「カメラ、ルーター」と注記されてた。watchOSもある。ここまで降りてこられるなら、次は監視カメラが自分で「これは荷物です」って判定してタグを打つとか、そういう方向にすぐ行くんだと思う。

それと、返事を書くAIと命令を実行するAIが、だんだん別々の生き物になっていく感じもある。前者は大きいまま、後者は小さくなっていく。

正直に言うと、これ単体で「AIすごい」とはならない。おしゃべりできないし、汎用の賢さは1.2Bのモデルに負ける。でも、手元のラズパイやスマホに29MB置くだけで、自分のアプリが自然な言葉で操作できるようになる、というのは、去年までは普通にクラウド課金が前提だった話。越えたのはそこ。小さくなった、じゃなくて、小さくなったから自分の持ち物の中に入った。そっちが本題。
