# StemDeck ― 曲を6本にばらすAIが、ノートパソコンの中だけで完結してしまった

[[tag/音楽制作]] [[tag/オープンソース]] [[tag/ローカルAI]] [[tag/demucs]] [[tag/StemDeck]]

StemDeckという道具が出てきた。

手元のMP3やWAVを放り込むと、その曲をボーカル、ドラム、ベース、ギター、ピアノ、その他の最大6本に分けてくれる。分けたあとはDAWみたいなミキサー画面が開いて、ボーカルだけ消す、ドラムだけ聴く、好きな組み合わせで書き出す、がひと通りできる。AIがどこにいるかというと、音の波形を見て「ここはボーカル」「ここはドラム」と振り分ける部分。

Metaが公開している Demucs というニューラルネットが担当している。で、それが全部自分のパソコンの中で終わる。アカウントいらない。音源をどこにもアップロードしない。無料。ライセンスはApache 2.0。

え、こんなん出ちゃったんだ、と思った。

私はこの手のこと、ずっとクラウドの仕事だと思っていた。Moises とか LALAL.AIとか、サイトに登録して、曲をアップロードして、クレジットを消費して、月いくら払う。あの流れが当たり前だと思い込んでいた。だから「ローカルで、無料で、全部」と書いてあるのを見て、正直まず疑った。どうせGPUがいるやつでしょ、と。私のノートにGPUは載っていない。

でも調べていくうちに、ちょっと話が変わってきた。

中身を開けると、使っているのは htdemucs_6s という6本ぶんのモデルで、パラメータは26,904,156個。数えたら重みは102.6MiBぶんだった。小さい。そして面白いのはここからで、このモデル、新しくない。Demucs の 4.0.1 がPyPIに上がったのは2023年9月7日。つまり3年近く前のものが、そのまま使われている。StemDeck 側もわざわざ 4.1 未満に固定していて、理由まで設定ファイルにコメントで書いてある。4.1が入れた新しい依存が、Intel版のMacでビルドできなくなるから、と。

だから「すごいAIが出た」話ではない。出たのはモデルじゃなくて、配り方のほうだった。

Windows用は700MBくらいのZIPを解凍して、中の実行ファイルをダブルクリックするだけ。Pythonも同梱されている。初回だけモデルを取りに行って、あとはオフラインで動く。これ、地味だけどけっこう効く。私は最初、自分でPythonから入れようとして `pip install torch` を素直に打って、5.2GBの環境ができあがった。中身を見たらCUDA関連のパッケージがぎっしり入っていて、GPUのない私には一生使わないものだった。あれは無駄だったなと思う。最初からCPU専用に絞って包んでくれているほうが、ずっとありがたい。

曲.mp3
  ↓  Demucs htdemucs_6s（26.9Mパラメータ／102.6MiB）
  ├─ vocals  ボーカル
  ├─ drums   ドラム
  ├─ bass    ベース
  ├─ guitar  ギター
  ├─ piano   ピアノ
  └─ other   その他
  ↓
ブラウザのミキサー画面（localhost:8000）

で、肝心の速さ。GPUなしで本当に終わるのか、気になったので実際に回してみた。スレッドを2本に絞って、CPUだけで。

1分の音源で46.28秒、メモリのピークは1,908MiB。4分の音源だと135.57秒、ピークは2,430MiB。

4分の曲を6本に分けるのに2分16秒。メモリのピークは2,430MiB。

正直に書いておくと、この数字は計算の重さを測ったもので、分けた音そのものはまだ聴けていない。試した環境から公式の重みファイルを落とせなくて、同じ形・同じ設定のまま中身を差し替えて回した。だから時間とメモリは信じていいけれど、音の良し悪しについて私はまだ何も言えない。あと、StemDeck には品質を上げる設定があって、そっちにするとモデルを2回通すので時間はだいたい倍になる。上の数字は標準のほう。

つまり4分の曲を待つのに2分ちょっと。実効5.8GBのメモリでも、2.4GBならまだ余裕がある。しかもこれは2スレッドでの数字だから、コアをもっと使えるならさらに縮む。コーヒーを淹れて戻ってきたら終わっている、くらいの体感。曲を聴きながら待つには長いけど、聴きたい曲を1本ずつ処理していくぶんには全然許せる。ここは正直、思っていたよりずっと現実的だった。

ただ、いいことばかりではない。6本に分けます、という売り文句のうち、ピアノはあまり信用しないほうがいい。これは私の感想じゃなくて、Demucs 自身のドキュメントに書いてある。ギターは「まあまあ」、ピアノは「他の音の混入とノイズが多い」と、作った本人たちがはっきり認めている。だから実際に使えるのはボーカル、ドラム、ベース、あとはその他、というあたりだと思っておいたほうがいい。

あと「モデルは約170MB」と書いてあるけれど、初回に落ちてくるのはそれだけじゃない。分離のモデルに加えて、テンポを取るもの、曲の構成（イントロやサビ）を推定するもの、ボーカルをさらに主旋律とコーラスに割るもので、合わせて4種類ぶん取りに行く。ディスクの見積もりは少し多めにしておいたほうがいい。

それと、いま出ている版はまだ番号が0.17.0で、更新のペースがとにかく速い。8月半ばに0.9、0.10、0.11と数日おきに上がって、そこから半月で0.17。直近の変更は9月4日。つまり今日触ったものと来月触るものは、たぶんけっこう違う。安定しきったソフトを求めているなら、もう少し待ったほうがいいのかもしれない。私は待てないタイプなので触るけれど。

始め方は2通りある。楽なのは公開されているZIPを取ってきて解凍して、中の StemDeck.exe を叩くほう。Pythonもffmpegも自分で入れなくていい。設定もログもモデルも、解凍したフォルダの中の data/ に全部入るので、フォルダごと別のドライブに移しても動く。

もう一方は、自分でソースから動かすやり方で、こっちは Python 3.12 以上と ffmpeg と uv が要る。`uv sync` して `uv run uvicorn app.main:app` を叩くと localhost:8000 でミキサー画面が開く。

Windowsだと ffmpeg は `winget install Gyan.FFmpeg` で入る。どちらもお金はかからない。長さの上限は初期状態で20分で、設定から最大60分まで伸ばせる。

私がこれで何をしたいかというと、まずは耳コピ。ベースだけ抜き出せば、耳で追えなかったフレーズがはっきり見える。あとはカラオケの練習用に、ボーカルを抜いた音を作る。

この2つだけでも、月額を払うより手元で待つほうを選ぶ理由になる。有料サービスに勝てるのは品質じゃなくて、待てること。そう考えると、私みたいに無料枠をやりくりしている人間にとっては、待ち時間って実はいちばん安い通貨なんだなと思う。

そしてこれ、たぶん音楽だけの話で終わらない。ランタイムを丸ごと同梱して、モデルは初回に取ってきて、ローカルにWeb画面を立てる。この包み方がうまくいったなら、文字起こしも、画像の整理も、同じ形で降りてくる気がする。「pipで入れてください」が、そのうち「ZIPを解凍してダブルクリック」に置き換わる。むしろ、そっちのほうが本命なんじゃないか。逆に、YouTubeのURLをそのまま食べられる機能がくっついているタイプは、いずれ削られる方向に動くと思う。便利すぎるものは、だいたいそうなる。

あと気になっているのは、まだ答えが出ていないほうの話で。速さと品質をお金で買うのと、手元で無料で待つのと、どっちが結局よかったのか。今はまだ両方が並んでいる。3年前のモデルがやっと普通のパソコンに降りてきたところで、その差はこれからも縮み続けるのか、それとも商用のサービスがまた引き離すのか。私はまだ決められないでいる。

とりあえず今日は、家にある曲をひとつ放り込んでみるところから。
