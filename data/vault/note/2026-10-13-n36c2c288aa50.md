# 【ローカルLLM】Strata｜125Bの巨大AIを12GBのゲーム用GPUと64GBのメモリで動かす無料ソフト｜1語で働く専門家は全体の2%、RTX 5070で毎秒94トークン

[[tag/ローカルLLM]] [[tag/自作PC]] [[tag/オープンソース]] [[tag/Qwen]] [[tag/Strata]]

1,250億パラメータのAIが、ふつうのゲーミングPCで動いてる。

こういう大きさのモデルって、ふつうはGPUのメモリが何百GBもあるサーバーで動かすものなんだよね。それをグラフィックボードのメモリ12GBで動かしてるソフトがあって、名前は Strata。作った人たちの計測だと、RTX 5070とメモリ64GBの組み合わせで、毎秒94トークンで答えを書く。人が読む速さよりずっと速い。

これを知ってから「大きいAIは家じゃ無理」っていう思い込みが、ちょっと崩れた。どこが崩れたのかを、なるべくかみ砕いて書いてみる。

まず Strata が何かというと、Qwen チームの Qwen3.8-Flash-Next という大きなモデルを自分のPCで動かすための、無料のソフト。MITライセンスで、Niko1221 さんとコントリビューターたちが GitHub で公開してる。Windows でも Linux でもよくて、NVIDIA でも AMD でもいい。

使い方もシンプルで、Windows なら START-HERE.bat をダブルクリックするだけ。GPUとメモリの量を調べて、合うサイズのモデルを選んで、約70GBをダウンロードして起動してくれる。終わるとブラウザでチャット画面が開く。OpenAI と同じ形の窓口も用意されてるから、ふだん使ってるコーディング用のAIツールをそこにつなぐこともできる。会話はPCの外に出ない。

じゃあ、なんで12GBに入るのか。ここがいちばん大事なところ。

このモデルは、ひとつの大きな頭じゃなくて、小さな専門家がたくさん集まったチームになってる。48階建てのビルで、各階に512人ずついるイメージ。全部で24,576人。

で、1語書くたびに、各階で呼ばれるのは512人のうち10人だけ。48階ぶん合わせても480人で、全体の1.95%しか働いてない。設定ファイルの数字から自分で数えたけど、ほんとに2%くらいだった。

つまり、全員をGPUの上に置いておく必要がそもそもない。ここに気づくと、話が一気に分かりやすくなる。

Strata は、仕事をPC全体で分担させてる。私は料理にたとえると分かりやすいと思った。GPU は手元の作業台。毎回必ず使う部分と、よく呼ばれる常連の専門家だけを置いておく。メモリは大きな冷蔵庫で、24,576人全員がここにいる。作業台にいない専門家が呼ばれたら、CPU が冷蔵庫の前でその場で調理する。しかも GPU と同時に動くから、お互いを待たない。

SSD は奥の倉庫。28.8GB の大きな対応表が置いてあって、1語ごとにほんの数行だけ取りに行く。

しかも作業台に置く常連は、会話しながら入れ替わっていく。コードの話をしてるとコードに強い専門家が、雑談だと雑談向きの専門家が手元に寄ってくる感じ。

ここで、作った人たちが書いてる「GPUのメモリが1GB増えると、作業台に置ける専門家が約700人増える」っていう数字を検算してみた。

専門家1人の大きさは、設定ファイルの値から計算すると491万5,200パラメータ。いちばん小さい Q2_0 版は1パラメータあたり2.5ビットに圧縮されてるから、1人あたり約1.54MB。1GiB を割ると699人。ぴったり合った。

これで分かるのは、このソフトにとっては GPU の速さより GPU のメモリの大きさのほうが効くってこと。手元に置ける常連が増えるほど、CPU が冷蔵庫の前で調理する回数が減るから。実際に、メモリ24GBの RTX 3090 なら毎秒100〜140トークンくらいになる見込みだって書いてある。

もうひとつ、速さの工夫に「先に当てずっぽうで書いて、あとで答え合わせする」仕組みがある。モデルの中に小さい下書き係がいて、次の数語を先に予想する。大きいモデルはそれを一気にチェックして、合ってるぶんだけ採用する。決めるのは毎回大きいモデルだから、答えの質は変わらない。それで1.6〜1.8倍速くなるらしい。

読んでいて、いちばん「へえ」ってなったのが、詰め込みすぎの罠の話。

RTX 4080 SUPER での計測で、作業台に置く専門家を453人ぶん、容量にして0.86GiB増やしただけで、速さが毎秒102トークンから13.7トークンまで落ちた。7倍遅い。

しかも遅いほうが、常連が当たる率はむしろ高かった。原因は、GPU のメモリが残り0になったとき、Windows が黙ってはみ出したぶんを本体のメモリに逃がすから。エラーにならないで、静かに遅くなる。

だから Strata の自動設定は、わざと少し余白を残すようになってる。これ、冷蔵庫をパンパンに詰めると逆に冷えなくなるのと同じで、AIじゃなくても身の回りによくある話だなと思った。予定をぎちぎちに入れた週ほど全部が遅れる、みたいなやつ。

あと、倉庫の対応表についても数えてみた。この表はもともと2,000万行×2,560列で、1マス1バイトの版だと51,200,000,000バイト、つまり47.68GiB。別の人が配ってる派生版のファイルの大きさと、バイト単位でぴったり一致した。Strata 本体は、それを28.8GBまで縮めて SSD に置いてる。

ちなみに、この表だけで512億パラメータある計算になる。「125B」には入ってないように見えるんだけど、どう数えてるのかは公式の説明を見つけられなかった。ここは私の読みで、確かめきれてない。

で、うちのPCで動くかというと……これ絶対うちの子じゃ無理だ〜。最低でも GPU のメモリ12GBと、本体のメモリ32GBが要る。うちはどっちも全然足りない。動かせる人、ほんとうらやましい。

メモリの量で選ぶモデルも変わる。32GBなら Coder 版で、専門家を半分に減らしたコード特化版。ただし中国語などのアジアの言語には弱くなるって書いてあるから、日本語で使いたい人は64GBで専門家が全員そろってる版を選んだほうがよさそう。

いまいちなところも正直に書いておくね。ダウンロードは70GBくらいあって、起動するとPCが1〜3分固まることがある。それと、圧縮には代償がある。派生版の計測だと、いちばん小さい Q2_0 は、8ビット版と「次の1語の第一候補」が一致するのが84.1%。大きめの IQ3_S なら90.0%。速さと賢さの交換になってる。

それでもいいなと思うのは、「巨大モデルはサーバーのもの」っていう前提を、ソフトの工夫だけで崩したところ。新しい部品は何も買ってない。働くのは2%だけ、っていう性質を正直に使っただけ。

これがここまで来たなら、次はモデルを作る側が、最初から家のPCで分担しやすい形にしてくるんじゃないかな。あと、パソコン選びで「GPUの速さ」より「GPUのメモリ量」を見る人が増えると思う。

自分のPCで動かす日が来たら、まずは余白を残す設定にしよう、とだけメモしておく。
