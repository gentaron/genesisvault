# DeepSeekがチャットテンプレートをやめた話

[[tag/AIエージェント]] [[tag/deepseek]] [[tag/オープンソース]] [[tag/プロンプト設計]] [[tag/開発環境]]

deepseek-recipe っていう小さいライブラリが9月10日に置かれてて、これがけっこう好きだったので書く。何をするものかというと、APIに投げたリクエストを、モデルが本当に読む一本の文字列に組み立てる部品。それだけ。推論はしない。

ツールも実行しない。通信もしない。Rustのライブラリに、Pythonから呼べる包みがくっついてて、ライセンスはMIT。DeepSeek本人が出してる。

で、なんでこれが面白いかっていうと。今までこの役目は、モデルの配布物に入ってるチャットテンプレート（Jinjaっていうテンプレート言語で書かれた、会話をプロンプトに変換する型紙）がやってた。ところがV4.1のモデルカードにこう書いてある。

今回はJinja形式のチャットテンプレートを同梱しません、って。代わりにこのライブラリを使ってね、と。型紙の配布をやめて、ライブラリを正本にしたってこと。地味だけど、これけっこう大きい宣言だと思う。

中で何をしてるかもわりとはっきりしてて、二段構えになってる。まず、飛んできたリクエストを Conversation っていう共通の形にいったん落とす。Messages形式でもChat Completions形式でもResponses形式でも、入口が違うだけで同じ形に畳む。

そのうえで、V4用かV4.1用かを選んでプロンプトに描き出す。戻りも同じ道具で解けるようになってて、モデルが吐いた生の文字列を、思考部分とツール呼び出しと本文に切り分けて、元の形式のレスポンスに組み直す。ストリーミングも同じ。

トークナイザを差せばトークンIDまで出せて、そのトークナイザも同梱されてる。数メガしかない。

実際に手元で描かせてみたんだけど、出てくるプロンプトの中身がちょっと予想と違って楽しかった。ツールを呼ぶところがJSONじゃない。DSMLっていう、XMLみたいなタグのブロックになってる。invoke で関数名を書いて、その下に parameter を並べる形。

しかも parameter に string という属性がついてて、これが true か false か。文字列ならそのまま書いて true、それ以外の数値や配列やオブジェクトはJSONにして false。

これ、たぶん逃げてるんじゃなくて、ちゃんと理由があるやつ。JSONの引数の中にコードとか改行とか引用符を入れると、エスケープが二重三重になって壊れる。

あの事故、みんな一度は踏んでると思う。文字列かそれ以外かを属性で外に出しちゃえば、中身はそのまま置ける。うまいなあと思った。

ツールの結果の戻し方も独特で、tool みたいな専用の役割じゃなくて、ユーザーのターンの中に tool_result のタグで入る。モデルから見ると「ユーザーが結果を持ってきた」ように見える形。

あと、思考モードを切ってても、空っぽの think タグの開きと閉じがちゃんと置かれる。開いてすぐ閉じる。位置だけ確保しておく感じ。

いちばん「へえ」だったのが、思考の深さの指定。サンプラーの設定じゃなくて、システム文の一行目に数字で書いてある。Reasoning Effort: 75、範囲は1から100、高いほど念入りに考えます、みたいな一文がそのまま入る。モデルへのお願いが、設定値じゃなくて地の文になってる。

V4のほうを見るともっと露骨で、同じ場所に長い英語の指示文がべたっと入る。手を抜くな、全部の分岐を潰せ、考えた過程を全部書け、みたいなやつ。V4.1でそれが数字ひとつに畳まれた、という並びになってる。文章でお願いしてたものを目盛りにした、という変化だと読める。

ただ、ここは正直ちょっと惜しくて。OpenAI風の low とか high とかで指定して入ってくると、出てくる数字が50か75しかない。1から100って書いてあるのに、この入口からだと二択。細かく効かせたいなら別の渡し方をしろってことなんだろうけど、うーん、ちょっとよく分かんない。

もうひとつ、出た当日にvLLM側で「deepseek-recipeに合わせる」っていうプルリクエストが立ってる。

何がズレてたかというと、ツール呼び出しの引数がきれいなJSONオブジェクトじゃないとき。二重にエンコードされた文字列が来ちゃったときの扱いが、Rustの描画部分と参照実装で違ってた。

片方は弾いて、片方は受け入れてた。こういうのが今まで実行エンジンごとに静かに違ってた、っていう話でもある。正解表が一箇所に決まると、こういうズレが可視化される。

微妙なところも書いておくと、まだ0.1で、コミットは初日の2つ。できないことのリストが長い。

確率のログ、JSONスキーマや正規表現での出力の縛り、ツール定義のstrict強制、一度に複数の候補を返すやつ、会話の保存と続きの取り出し、暗号化された思考、音声と動画。画像の前処理はOpenCVが要る。あと当然だけどDeepSeek専用で、標準を名乗ってるわけじゃない。使いたくなる人も限られてて、推論基盤を組んでる人か、プロンプトの実物を覗きたい人か、そのどっちか。

そう、その「覗きたい人」がわたし。本体のV4.1 Flashは5000億超えの重みで、うちのは非力だから絶対に無理。1メガのトークンが入るとか言われても、そもそも起動しない。いいなあ、動かせる人ほんとうらやましい。でもこのライブラリはpipで入って、GPUも重みも要らないの。モデルは動かせないのに、そのモデルが何を読まされてるかは、うちの子でも一文字残らず見られる。

デモの画面も付いてて、特別なトークンがどこに置かれてるか色分けして見せてくれる。これ、地味に嬉しかった。いつかちゃんとしたマシンで、この文字列を実際に食べさせるところまでやりたい。

で、これが来たなら次はたぶん、他のところも追いかけると思う。テンプレートの文字列をモデルと一緒に配るんじゃなくて、エンコーダをライブラリとして配る形。

型紙って、書き換えられるし、微妙に版がずれるし、誰の写しが正しいか誰も知らない状態になりがちだったので。あとツールの引数がJSONから離れていく流れも、たぶんもう少し広がる。JSONの中にコードを入れるのは、そもそも無理があったと思う。

「AIすごい」で終わる話ではぜんぜんない。むしろ配管。誰も見たがらないところ。でもここが揃わないと、上でどんなに賢いモデルを動かしても、ツールの引数がひとつ黙って壊れて、それが誰のせいか分からないまま終わる。そういう事故が減るだけの話で、減るだけの話がいちばん効いたりする。
