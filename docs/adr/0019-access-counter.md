# ADR-0019: サイト内アクセスカウンタ — KV への INCR をブラウザから叩く

**Status**: Accepted
**Date**: 2026-08-18
**Deciders**: gentaron

## Context

フッターに「このサイトが何回見られたか」を表示したい。数字は訪問者にも見える
ことが要件で、管理ダッシュボードの中にあるだけでは足りない。

このサイトの構成が選択肢を狭める。

- Astro は **完全な静的生成**（SSG）。ページを配る時点でサーバは何も数えない
- 動く場所は Vercel の関数（`api/`）だけで、こちらは **状態を持たない**。
  ファイルに書いてもデプロイ単位で消える
- 既に Umami を配線してあるが、あれは自分用の解析であって、
  訪問者に見せる数字を取り出す API ではない

つまり「数える」には、①ブラウザから叩く口と、②リクエストをまたいで残る場所、
の2つが要る。

## Decision

### 1. 数える場所は Redis (Upstash / Vercel KV) の REST API

無料枠で足り、`fetch` だけで話せる（SDK 依存を増やさない）。キーは2本:

- `gv:views:total` — サイト全体
- `gv:views:page:<path>` — ページ別

`INCR` は返り値が更新後の値なので、**加算と表示が1往復で済む**。
パイプラインで2本まとめて送る。

### 2. 未設定は「無効」であって「エラー」ではない

`KV_REST_API_URL` / `KV_REST_API_TOKEN`（Upstash 名でも可）が無ければ
`/api/views` は `{ enabled: false }` を返し、ウィジェットは出ない。
Umami の `PUBLIC_UMAMI_WEBSITE_ID` が空なら script を出さないのと同じ扱いで、
**環境変数を1組足すだけで有効になる**状態を既定にする。

### 3. パスの正規化はサーバ側に1本だけ置く

パスはクライアントから来て、そのままキーの一部になる。
`normalizePagePath` を通らない値はキーにしない（400 で返す）:

- 絶対パスのみ（`//host` や `https://` は拒否）
- `?`・`#` 以降は捨てる（`/x?utm=1` と `/x` を同じページとして数える）
- `..`・`\`・許可外文字・128文字超は拒否

**理由**: 検証を各所に散らすと、後から増えた呼び出し口が素通りする。
入口を1つにしておけば、そこだけ読めば安全性が判断できる。

### 4. 同じページは 30 分に 1 回しか数えない

`localStorage` に「そのパスを最後に数えた時刻」を置き、30 分以内の再訪は
`GET`（読むだけ）に切り替える。`sessionStorage` ではなく `localStorage` なのは、
**sessionStorage がタブ単位**だから — 記事を3つ別タブで開く読者を3人として
数えてしまう。ブラウザ側の緩い重複除去なので、**厳密なユニーク数ではない**
（別ブラウザ・シークレットウィンドウは別に数える）。

## Consequences

- フッターに数字が出る。KV 未設定なら何も出ない（見た目は現状のまま）
- `/api/views` は誰でも POST できる。カウンタは飾りなので、
  厳密性より「壊れないこと」を優先した。荒らされた場合の対処は
  キーを消して再開する（`gv:views:*` を削除）
- 表示できない障害（KV 落ち・ネットワーク断）では**数字を捏造せず隠す**。
  0 を出すと「誰も見ていない」という嘘になる
- 解析の正典は引き続き Umami。この数字は訪問者向けの表示であって、
  意思決定に使う指標ではない

## Alternatives considered

| 案 | 却下理由 |
|----|---------|
| Vercel Web Analytics の数値を表示 | 公開 API が無く、訪問者に見せる用途に使えない |
| Umami の統計 API を読む | 自己ホストの Umami が必要で、未稼働。依存が重い |
| 外部の無料カウンタ（画像カウンタ等） | 第三者に訪問者の IP が渡る。プライバシー方針と噛み合わない |
| 静的ビルド時の数値埋め込み | ビルド時点の値で固定され、「アクセス数」にならない |
