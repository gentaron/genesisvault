# LANDMINES — 一度踏んだ罠

同じ穴に二度落ちないための記録。**症状 → 原因 → 回避策**の3点セットで書く。

新しく踏んだら、抜け出した直後に書くこと。翌日には「なぜハマったか」を忘れている。
ここに書けるくらい理解できていないなら、まだ直っていない可能性がある。

---

## LM-001: ADR の番号が3回衝突していた

**症状**: `docs/adr/` に `0006` が2つ、`0008` が2つ、`0010` が2つ存在した。
「ADR-0010 を見て」が2つの別文書を指し、README とコードコメントが別の ADR を参照していた。

**原因**: 番号を採番する仕組みが無く、並行して書かれた ADR が同じ次番号を選んだ。
ファイル名が違えば `git` は何も言わない。

**回避策**: 後発側を採番し直した（`0012` / `0013` / `0014`）。
`bun run verify` が番号の重複を検出して失敗するようになっている。
新しい ADR を書く前に `docs/almanac/INDEX.md` で最大番号を確認すること。

## LM-002: 生成した JSON を Biome が整形してドリフト扱いになる

**症状**: `bun run config:schema` で生成した `config/pipeline.schema.json` が、
`biome check --write` のあとテストで「Zod スキーマと不一致」と判定される。

**原因**: 生成側は `JSON.stringify(..., null, 2)`、Biome は独自の整形（短い配列を1行化）。
両者が同じファイルを奪い合い、どちらを実行したかで内容が変わる。

**回避策**: 生成物を Biome の対象から外す（`biome.json` の `!config/pipeline.schema.json`）。
**生成物は整形しない** — これは他の生成ファイルを追加するときにも効く原則。

## LM-003: `astro check` には既存の型エラーが17件ある（新規ではない）

**症状**: 何も壊していないのに `bunx astro check` が 17 errors を返す。

**原因**: 大半は `@ai-sdk/*` の各プロバイダーが `LanguageModelV3` を返すのに対し、
`ai` v5 の `LanguageModel` 型が `V2` を指しているというSDK 間のバージョン差。
実行時は動く。型だけが合っていない。

**回避策**: `as unknown as` で握り潰さないこと。実害はなく、SDK 側の更新で解消する種類の不一致で、
キャストするとSDK が本当に壊れたときに気づけなくなる。
`bun run verify` は**件数のラチェット**で管理している（`config/quality-baseline.json`）。
増やさなければ通る。減らせたらベースラインを締める。

## LM-004: Biome の指摘105件を一括修正したくなるが、やらない

**症状**: `bun run lint` が 105 errors。「まとめて `--write` すれば0になる」と思える。

**原因**: 大半が整形（インデント・import 順）で、機械的には直る。

**回避策**: やらない。AGENTS.md §3.3 が整形変更と論理変更の混在を禁じている。
85ファイルの整形差分に本質的な変更が1行混ざると、レビューで発見できない。
触ったファイルだけを `biome check --write <file>` で直し、
全体はラチェット（`config/quality-baseline.json`）で「増やさない」だけ担保する。

## LM-005: 2026年2月に同じ日付の記事が2本ある日がある

**症状**: `content-lint` が 2026-02-21 / 02-22 / 02-27 に `duplicate_date` 警告を出す。

**原因**: 冪等化（`.pipeline-state.json`）を入れる前に、ワークフローが同日に2回走った。

**回避策**: 過去分は歴史なので消さない（警告のまま残置）。
現在は INV-005 で防いでいる。この警告が**新しい日付で**出たら、それは冪等性の破れなので調査すること。

## LM-006: README の数値が実態から乖離する

**症状**: README に「192 ユニットテスト」と書いてあるが、実際は 336 件だった。

**原因**: テストは増え続けるが、README の数字は手で書かれていて誰も更新しない。

**回避策**: 数えれば分かる数字を散文に埋め込まない。
どうしても書くなら「`bun run test` で確認」と書くか、生成する。
同種の乖離は「5エージェント」「8エージェント」の記述揺れにもあった（実際は8）。
