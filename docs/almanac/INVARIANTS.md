# INVARIANTS — 壊してはいけない前提

ここに書かれていることが偽になったら、それはバグ。
「リファクタしたら偶然壊れていた」を防ぐための、明示的な契約リスト。

各項目には **どうやって守られているか**（テスト／ゲート／人間の注意）を併記する。
「人間の注意」しか書けない項目は、いずれ破られる。テストに落とせないか常に疑うこと。

---

## 設定・パイプライン

### INV-001: `config/pipeline.json` が唯一の設定ソース

エージェント名簿・プロバイダーチェーン・ルーティング・品質ゲート閾値は
すべて `config/pipeline.json` に書かれ、TypeScript 側は**自前の既定値を持たない**。

同じ数値が2箇所にあると、片方だけ直して静かにズレる。
`src/lib/pipeline/config.ts` は不正な設定を**起動時に例外で落とす**。
黙って既定値にフォールバックしてはいけない（それは設定ミスを隠す）。

- **守り方**: `tests/pipeline-config.test.ts` / `bun run verify` のスキーマ・整合性チェック

### INV-002: `config/pipeline.schema.json` は生成物であり、手で編集しない

Zod スキーマ（`src/lib/pipeline/config.ts`）が正典。JSON Schema はそこから導出される。

- **守り方**: `bun run verify` がドリフトを検出。再生成は `bun run config:schema`
- **注意**: Biome の整形対象から除外済み（`biome.json`）。外すと整形と生成が競合する → LM-002

### INV-003: API キーが1つも無くてもパイプラインは落ちない

`buildProviderChain()` は環境変数が空なら空配列を返す。
そのときパイプラインはテンプレート記事にフォールバックする（AGENTS.md §10.4）。

「キーが無いから例外」は許されない。CI・ローカル・フォークのすべてで
最低限の動作確認ができる必要がある。

- **守り方**: `tests/ai-providers.test.ts`（キー無しでチェーン長 0）

### INV-004: 検証はオフラインで完結する

`bun run verify` は **LLM・ネットワーク・API キーのいずれも要求しない**。
生成は安く、検証が高い。その検証が外部要因で不安定なら、品質ゲートとして機能しない。

判断が要らないチェックを LLM に投げてはいけない。ルールで落とせるものはルールで落とす。

- **守り方**: 設計上の制約。`scripts/verify.mjs` に外部通信を追加しないこと

### INV-005: パイプラインは1日1記事（冪等）

同じ日付の記事が既にあれば、パイプラインは何もせず正常終了する（AGENTS.md §10.2）。
ワークフローの再実行や手動実行で記事が二重に生えてはいけない。

- **守り方**: `.pipeline-state.json` + 生成前の存在チェック。`content-lint` の `duplicate_date` が事後検出
- **既知の例外**: 2026-02-21 / 02-22 / 02-27 は冪等化以前の重複（警告として残置）

## コンテンツ・継続性

### INV-006: エージェント ID（VE-xxx）は永久に不変

ID は公開済み記事の frontmatter に焼き込まれている（163記事）。
名前や役割は変えられるが、**ID の付け替えは過去記事を嘘にする**。
新しい役割には新しい番号を振ること。

- **守り方**: `content-lint` の `agent_credit`（記事の ID が名簿に無ければエラー）

### INV-007: 継続性台帳の金額は「最高到達点」であり、逆行しない

「貯金300万円達成」の記事のあとに「貯金200万円達成」の記事が出てはいけない。
`data/continuity-ledger.json` は到達済みマイルストーンの正典で、
Vera → Edda が逆行禁止ブリーフを CEO/Writer に注入する。

- **守り方**: `tests/continuity.test.ts`、Mira（VE-008）の投稿後更新

### INV-008: 継続性の正典は本パイプラインが生成した記事

`src/content/posts/` が正典。`gensnotes_*.md`（旧ブログの WXR エクスポート）は
**文体・テーマの参照源であって、事実の参照源ではない**。混ぜると過去の設定が復活する。

- **守り方**: `config/pipeline.json` の `references` で legacy / current を分離

### INV-019: 継続性は指示ではなくゲートで守る。対象は金額に限らない

「過去の到達点を下回るな」をブリーフに書くだけでは守られたか誰も確認しない。
逆行した記事はいつも通り緑で公開され、気づくのは読者だけになる。
だから最後は決定的なチェック（`detectRegressions()`）が止める。

対象は金額だけではない。継続日数・年数・冊数も同じ扱いにする。読者から見れば
「先週120日目と書いた瞑想が今日30日目になっている」のも「貯金が300万から200万に
戻る」のも同じ矛盾で、片方だけ守るのは筋が通らない。

守るのは3箇所すべて。**書き手の原稿**（差し戻して書き直させる）、
**校正後の本文**（Iris は本文を書き換えるので再確認する）、
**テンプレートのフォールバック**（AI 全滅の日にだけ逆行が出るのが一番見つけにくい）。

回想は矛盾ではない。「始めた頃は貯金100万円だった」は通す。

- **守り方**: `tests/continuity.test.ts` の `detectRegressions` 節、
  `scripts/auto-post.mjs` の Continuity Gate、`generateFallbackPost` の述語

### INV-020: 外部トレンドの取り込みは fail-soft で、検証を汚さない

`src/lib/agents/trends.ts`（VE-010）はこのリポジトリで唯一、外へ通信する
サブシステム。設計は審査層とちょうど逆にする。

- **取れなければ諦める**。HN や Stooq が落ちている日に日記が出ないのは割に合わない。
  失敗は例外ではなく `degraded` として記録し、パイプラインは続行する
- **`bun run verify` からは呼ばない**（INV-004）。検証はオフラインで完結する
- **API キーを要求するソースを足さない**（INV-003 と同じ理由）
- **外の数字を個人の事実にしない**。相場の数値が継続性台帳に入ると、到達不能な
  下限が居座り、以後すべての原稿が逆行判定で落ちる

- **守り方**: `tests/trends.test.ts`（fetch を差し替え、壊れた応答でも落ちないこと）、
  `continuity.ts` の `MARKET_NOISE` 除外、`checkConfigIntegrity()` の待ち時間上限

## 囲い（審査層）

### INV-011: 審査役は書き手より弱いモデルを使わない

書き手が雑でも、審査が厳しければ差し戻して直せる。審査が甘いと、
雑なものがそのまま外に出て、その先に止める仕組みは無い。

さらに悪いことに、**見逃しは何も表示しない**。エラーも警告も出ず、全部緑で通る。
運用していると誤検知だけが目につき、見逃しは永久に発見されない。
コストが非対称なので、配分も非対称にする。

- **守り方**: `checkConfigIntegrity()` が VE-006 の最優先モデルと VE-002 のそれを比較して失敗させる。
  `tests/ai-routing.test.ts` と `bun run verify` の「囲い」節でも検証

### INV-012: 審査できなかった原稿は通さない（fail-closed）

プロバイダーが無い・全滅した・不正な出力しか返らない場合、
`review.ts` は**不合格**を返す。例外を投げて素通りさせたり、既定で通過させたりしない。

閉じられないゲートは、閉じたことにする。静かに悪いものを出すより、何も出さないほうがよい。

- **守り方**: `judgeArticle()` の全失敗経路が `rejectedVerdict()` を返す。`tests/review.test.ts`

### INV-013: 合否はコードが決める。モデルは観察だけを返す

判定モデルに総合点や合否を出させない。項目ごとの観察だけを受け取り、
加重集計は `computeVerdict()` が rubric の重みから決定論的に行う。

採点者が自分の点数を申告する仕組みは、甘くなる方向にしか壊れない。
**モデルが出さない数字については、モデルは甘くなりようがない。**

未報告の項目は 0 点として扱う。沈黙は合格ではない。

- **守り方**: `JudgeOutputSchema` に総合点のフィールドが無い。`buildJudgePrompt()` は
  総合点を書かないよう明示し、テストがその文言を固定している

### INV-014: 減点には原稿に実在する引用が要る

`verifyEvidence()` が引用の実在を照合し、実在しない引用を伴う指摘は破棄する。
引用を捏造する審査役は「厳しい」のではなく「当てにならない」。

この検証自体はモデルを使わないので、審査役の信頼性を決定論的に測れる。

- **守り方**: `tests/review.test.ts`（捏造引用の破棄）

### INV-015: 囲いには正常系の対照群を必ず置く

不良事例しか無いゲートは「全部落とす」で満点を取れてしまう。
そして厳しすぎるゲートは、運用で緩められて最終的に無効化される。

`tests/fixtures/gate/` には正常な記事を最低1件置き、それを1つも誤検知しないことを検証する。

- **守り方**: `tests/gate-calibration.test.ts` の false positives 節、`bun run verify` の「囲い」節

### INV-016: 既知の死角には、必ず受け皿が宣言されている

ルールで捕まえられない不良（一般論だけの記事、テーマのすり替え）は
`blindspot` としてゴールデン事例に記録し、**どの criterion が代わりに捕まえるか**を manifest に書く。

受け皿の無い死角は、ただの穴。

- **守り方**: `bun run verify` の「既知の死角に審査側の受け皿がある」、`tests/gate-calibration.test.ts`

## 受け渡し（Linear → VAIZ）

### INV-017: `agent-ready` を貼る前に、4つの機械的な制約を全部通す

`agent-ready` + Todo の Issue は、別リポジトリ（VAIZ）の無人パイプラインの
**入力キュー**である。1件置くと、その晩に動画が1本できる。
このラベルは元々「人間による着手承認ゲート」だったので、機械が貼る以上、
人間が担っていた歯止めを機械で置き換えないと、ただゲートが消えたことになる。

`scripts/linear-video-brief.mjs` は、Issue を作る**前に**次を全部通す。
どれか1つでも欠けたら、作らずに終わる。

| 制約 | 破れたときに起きること |
|------|----------------------|
| 冪等（台帳 + `gv:source=` マーカー） | 同じ記事から動画が2本できる |
| 背圧（Todo の未着手 < `maxQueued`） | VAIZ が詰まっているのにキューだけ伸び続ける |
| 検証（`lintVideoBrief()` が空） | 壊れたブリーフから動画が1本できる |
| 転載検出（逐語一致 ≤ `maxVerbatimChars`） | ゲート記事の本文が Linear に転載される |

この経路の失敗はすべて**静かである**。Issue は作られ、ワークフローは緑で終わり、
気づくのは動画ができてからになる。だから「警告を出して続行」を選んではいけない。
**作らないことは常に安全側**で、記事のほうは既に生成・検証・push が済んでいる。

- **守り方**: `tests/video-brief.test.ts`（決定論チェック全ルール）、
  `tests/pipeline-config.test.ts`（境界値の整合）、`bun run verify`
- **既知の穴**: 重複検出は Linear の新しい100件しか見ない。それより古い記事は
  台帳だけが守っている（台帳のコミットが失われると再送されうる）

### INV-018: 動画ブリーフの尺・シーン数はモデルが決めない

「45〜60秒、縦型。6〜8シーン。」は VAIZ の `PlanSchema` が実際に強制する
受け入れ条件であって、その動画についての意見ではない。
`config/pipeline.json` の `videoBrief` に書き、`renderVideoBrief()` が組み立てる。

VE-009 が返すのは中身の5フィールドだけで、Markdown は1文字も返さない。
モデルが別の見出しや別の尺を書けるようにすると、**下流が受け付けない企画を
毎晩生成して Issue が差し戻され続ける**——しかもその原因は1リポジトリ先にある。

- **守り方**: `RunaOutputSchema` に Markdown を返す口が無い。
  `tests/video-brief.test.ts` が「尺は config から来る」ことを固定。
  `checkConfigIntegrity()` が境界値の反転を検出

## 課金・セキュリティ

### INV-009: ペイウォールの判定はサーバー側のみ

HMAC 署名 Cookie の検証がすべて（Phase δ / ADR-0004）。
クライアント側の表示制御は UX であって、セキュリティ境界ではない。

- **守り方**: `tests/paywall-server.test.ts`, `e2e/paywall-bypass.spec.ts`

### INV-010: ゲート記事の本文は検索インデックスに載せない

Pagefind は静的インデックスを公開ディレクトリに吐く。
ゲート記事の本文に `data-pagefind-ignore` が付いていないと、
**ペイウォールの裏側が検索インデックス経由で丸ごと漏れる**。

- **守り方**: `src/layouts/BaseLayout.astro` の該当属性。E2E で本文非露出を確認
