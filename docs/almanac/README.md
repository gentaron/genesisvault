# Almanac — このリポジトリの記憶

コードには「何をしているか」は書いてある。書いていないのは **「なぜそうしたか」「何を壊してはいけないか」「どこで一度転んだか」** の3つで、
これは人が辞めても AI のコンテキストが切れても失われる。ここはその3つを沈殿させる場所。

モデルは数ヶ月で入れ替わる。蓄積した文脈と固めた手順のほうが寿命が長い。
だから「次のモデルを待つ」より「今のモデルで手順を固める」ほうを選ぶ。

## 構成

| ファイル | 中身 | いつ書くか |
|---------|------|-----------|
| [INVARIANTS.md](./INVARIANTS.md) | 壊してはいけない前提 | 前提を作った／変えたとき |
| [LANDMINES.md](./LANDMINES.md) | 一度踏んだ罠と、その回避策 | ハマって、抜け出したとき |
| [INDEX.md](./INDEX.md) | ADR・Runbook の自動生成インデックス | 手で書かない（`bun run almanac` で再生成） |
| [`../adr/`](../adr/) | 設計判断の記録（不可逆な決定の理由） | 選択肢が複数あり、どれかを選んだとき |
| [`../runbooks/`](../runbooks/) | 手順書（壊れたときに読むもの） | 同じ操作を2回以上したとき |

## 使い方

**読むとき（作業前）**

1. `INVARIANTS.md` — これから触る領域の前提を壊さないか確認する
2. `LANDMINES.md` — 同じ穴に落ちない
3. `INDEX.md` から関連 ADR を引く

**書くとき（作業後）**

PR テンプレートの「記憶に残すこと」欄がチェックリストになっている。
面倒でも、ハマった直後に書くのが唯一のタイミング。翌日には理由を忘れている。

書く粒度の目安:

- **1行で書けないなら ADR**（背景・選択肢・決定・結果）
- **1行で書けるなら LANDMINES**（症状 → 原因 → 回避策）
- **「〜であること」と言い切れるなら INVARIANTS**

## 自動化されていること

- `bun run almanac` — `INDEX.md` を `docs/adr/` と `docs/runbooks/` から再生成
- `bun run verify` — ADR 番号の重複と `INDEX.md` の陳腐化を検出して失敗する

インデックスを手で更新する必要はない。というより、手で更新しても次の再生成で上書きされる。
